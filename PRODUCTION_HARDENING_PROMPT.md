# Промпт production-доработки Deep Context Agent

Ты — ведущий Python-инженер и специалист по надёжности LLM-агентов. Исправь
проект по фактическому ручному логу. Работай последовательно, после каждого
этапа запускай относящиеся к нему тесты и не переходи дальше при ошибках.

## Обнаруженные дефекты

1. Интерактивный `chat` принимает многострочную вставку как отдельные запросы.
2. При команде без переданного содержимого агент угадывает текст и создаёт
   посторонние файлы.
3. Старый retrieval и длинный `thread main` подмешивают прежние тесты и
   неподтверждённые утверждения.
4. После `429 rate_limit_exceeded` неудачный пользовательский ход может остаться
   в checkpoint и повлиять на следующий запрос.
5. Retry всего agent graph опасен повторным выполнением файловых tools.
6. После timeout веб-поиска агент может сослаться на старый результат как на
   только что открытую страницу и указать неверную дату проверки.
7. Проверяемый отчёт охватывает изменения файлов, но не чтение, retrieval,
   web-search/fetch и runtime metadata.
8. Итоговый `PASS` формируется самой LLM и игнорирует обязательные сбои,
   неподтверждённые действия и неверное содержимое.

## Обязательная реализация

### 1. Ввод

- Добавь в `chat` режим `/paste`, читающий строки до `/end`, и `/cancel`.
- Добавь `ask --file PROMPT.txt` и `ask -` для чтения одного многострочного
  запроса из stdin.
- Запрещай одновременную передачу позиционного запроса и `--file`.
- Ограничь размер prompt-файла и выдавай понятную ошибку UTF-8/размера.

### 2. Полнота команды

- До LLM распознавай явно незавершённые изменяющие команды: окончание двоеточием,
  обещанный «точный текст» без текста, «добавь строкой» без значения.
- Для такой команды не вызывай модель и tools, не создавай файл и возвращай
  детерминированный запрос недостающих данных.
- Закрепи в системном промпте запрет угадывать путь, содержимое и продолжение.

### 3. Контекст

- Не добавляй автоматический retrieval в точные файловые, операционные и длинные
  самодостаточные запросы; `search_context` при этом остаётся доступен модели.
- Ограничь автоматически добавляемый контекст отдельным символьным бюджетом.
- Помечай auto-retrieval как недоверенные данные; никогда не считай старый
  assistant-ответ доказательством текущего состояния файлов или веб-страницы.

### 4. Ошибки и повторные попытки

- Повторяй transient model errors только через `ModelRetryMiddleware`, то есть
  на уровне одного model call, не повторяя agent graph и tools.
- Используй настраиваемый exponential backoff, jitter и конечный предел.
- После исчерпания попыток пробрасывай ошибку; LLM не должна продолжать и
  объявлять успех.
- Перед graph invoke снимай список строк checkpoint/writes текущего thread. При
  исключении удаляй только добавленные этим неудачным ходом строки. Следующий
  запрос не должен видеть и выполнять провалившуюся команду.
- Web search повторяй ограниченно при transient timeout; после исчерпания
  возвращай явную ошибку, а не старый факт.

### 5. Доказательства

- Формируй `Verified tool operations` программно для всех текущих tool calls:
  runtime, context, read/list/search файлов, изменения, web search и page fetch.
- Не выводи содержимое файлов, ключи или большие веб-фрагменты в audit.
- Если запрос требует tool, а успешного результата нет, отчёт обязан показывать
  `none` или фактический `error/denied/not_found`.
- Точная версия/дата веб-факта считается проверенной только при успешном
  `fetch_web_page` текущего хода. Tool должен возвращать UTC `checked_at`.
- Model/provider — несекретные runtime metadata; API key никогда не выводится.

### 6. Проверки

- Напиши unit-тесты CLI `/paste`, stdin и `--file`.
- Напиши тесты незавершённой команды без model/tool call.
- Проверь ограничение retrieval по типу и символьному бюджету.
- Fake model должен упасть один раз, успешно повториться на model-call уровне и
  не продублировать tool.
- При окончательном исключении checkpoint должен вернуться к исходному набору,
  а следующий запрос не содержать провалившуюся команду.
- Проверь audit для `read_file`, `web_search`, `fetch_web_page`, mutation и
  отсутствующего обязательного tool.
- Проверь web retry и окончательный timeout без реальной сети.
- Сохрани существующие тесты root-delete, внешнего пути, точного чтения,
  миллионов строк и сотен документов.

### 7. Финальная приёмка

Выполни Ruff lint/format, полный pytest, CLI help, `doctor`, изолированный live
smoke-test на доступном провайдере и негативные проверки. Используй отдельные
`AGENT_WORKSPACE`, `AGENT_DATA_DIR` и новый thread. Не объявляй production-ready,
если есть непредусмотренный skip/fail, ложный `PASS`, неподтверждённый веб-факт,
повторное изменение файла или секрет в выводе. Обнови README и
`IMPLEMENTATION_STATUS.md` фактическими командами и результатами.
